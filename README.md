# Music Playlist Manager

A beginner-friendly full-stack app for keeping a private catalogue of song **metadata** and organizing songs into playlists. It does not upload, stream, or play copyrighted audio.

## Problem, users, and features
Music fans often want a simple way to organize titles, artists, albums, genres, and durations. Each registered user has a private song library and playlists. No admin role is needed. Register, log in, add/search/delete songs, create/rename/delete playlists, add/remove songs from playlists, and log out. Deleting a playlist does not delete its songs; deleting a song removes its playlist memberships.

## Technology and architecture
HTML5, CSS3, vanilla JavaScript (`fetch`) → Express/Node REST API → Supabase PostgreSQL. Supabase Auth issues access/refresh tokens. The browser sends access tokens to Express; Express validates them with Supabase Auth and forwards the same JWT to a per-request Supabase client. PostgreSQL RLS limits all records to their owner. Only the public/publishable (legacy anon) key is used; never use a service-role key.

## Prerequisites
Install [VS Code](https://code.visualstudio.com/), [Node.js LTS](https://nodejs.org/), and [Git](https://git-scm.com/). Create a free [Supabase](https://supabase.com/) account. In VS Code choose Terminal → New Terminal. Check:
```powershell
node -v
npm -v
git --version
```
Each command should print a version. If a command is unrecognized, restart VS Code after installation.

## Supabase setup
1. Create a Supabase project and securely retain its database password (do not add it to this app).
2. In SQL Editor, open `database/schema.sql`, paste all of it, click Run.
3. In Table Editor, confirm `playlists`, `songs`, `playlist_songs` exist.
4. Under Authentication → Providers, enable Email. For simple local testing, either confirm sign-up emails or disable email confirmation in the project's authentication settings. Use real email addresses if confirmation is enabled.
5. In Project Settings → API (or Connect/API Keys in the current dashboard), copy Project URL and publishable/anon key. Do not copy the secret/service-role key.

## Local installation (Windows PowerShell)
From the project root in VS Code:
```powershell
cd backend
npm install
Copy-Item .env.example .env
```
Edit `backend/.env`:
```dotenv
PORT=3000
NODE_ENV=development
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
```
The `.env.example` is safe to commit; `.env` is private. `PORT` sets the local port; `NODE_ENV` describes the environment; `SUPABASE_URL` and `SUPABASE_ANON_KEY` identify your project for non-privileged access. Do not put secrets in frontend code. `npm install` downloads dependencies and creates/updates the lockfile. Run:
```powershell
npm start
```
Expect `Music Playlist Manager: http://localhost:3000`. Visit that address, not `frontend/index.html` directly. macOS/Linux: use `cp .env.example .env` instead of `Copy-Item`. If port 3000 is busy, change `PORT`.

## How to use
Sign up with an email/password of 8–72 characters, confirm your email if required, then log in. Add a song (duration is seconds; 0 means unknown). Create a playlist, click Open, select a song, and Add to playlist. Search by title/artist/album/genre. Use Remove to remove membership, Delete to remove the entire song or playlist. Confirm destructive actions. Logging out clears the session from browser memory; reloading the page also requires logging in again.

## API
JSON request/response; errors use `{ "error": "message" }`. All routes except health and auth require `Authorization: Bearer ACCESS_TOKEN`; all private records belong to the authenticated user. There is no administrator.
| Method | Path | Input | Success |
|---|---|---|---|
| GET | /api/health | none | 200 `{ok:true}` |
| POST | /api/auth/signup | `{email,password}` | 201 `{message,session}` (session may be null until confirmation) |
| POST | /api/auth/login | `{email,password}` | 200 `{session}` |
| POST | /api/auth/refresh | `{refresh_token}` | 200 `{session}` |
| GET | /api/playlists | none | 200 array |
| POST | /api/playlists | `{name,description?}` | 201 playlist |
| PATCH | /api/playlists/:id | `{name?,description?}` | 200 playlist |
| DELETE | /api/playlists/:id | none | 200 `{ok:true}` |
| GET | /api/songs | none | 200 array |
| POST | /api/songs | `{title,artist,album?,genre?,duration_seconds?}` | 201 song |
| DELETE | /api/songs/:id | none | 200 `{ok:true}` |
| GET | /api/playlists/:id/songs | none | 200 entries with nested song |
| POST | /api/playlists/:id/songs | `{song_id}` | 201 `{ok:true}` |
| DELETE | /api/playlists/:id/songs/:songId | none | 200 `{ok:true}` |

Validation errors are 400, authentication failures 401, missing or non-owned resources 404 (where queried by ID), and unexpected server errors 500. Database RLS also protects list and delete operations.

## Testing checklist (manual; requires your own Supabase project)
- GET `http://localhost:3000/api/health` returns `{"ok":true}`.
- Sign up/confirm/login; wrong password is rejected.
- Add two songs and a playlist; reload after logging in again; records persist.
- Search for an artist; matching songs appear.
- Add a song to a playlist; duplicate addition is prevented (already-added songs disappear from selector).
- Remove membership; song remains in library.
- Delete a playlist; songs remain. Delete a song; membership disappears.
- Try empty title, negative duration, very long name: form or API rejects it.
- API without a token returns 401; another account cannot view/edit the first account's records.
- Resize browser to mobile width; columns stack.
- Log out; private dashboard is hidden. Reload; log in again.

## Troubleshooting
- `node`/`npm` not recognized: install Node.js LTS, restart terminal.
- `Configure backend/.env`: create `backend/.env` and fill URL/key.
- Signup/login fails: check Supabase Authentication settings, email confirmation, and credentials.
- `Request could not be completed`: confirm SQL executed and Supabase URL/key belong to same project; inspect backend terminal and Supabase logs without sharing secrets.
- 401: log in again; token may have expired.
- Port in use: change `PORT` in `.env` and restart.
- `Failed to fetch`: start backend with `npm start` and open localhost at the printed port.
- If Supabase schema was modified, rerun compatible SQL and verify policies.

## Security and limitations
Passwords are handled by Supabase Auth; no plaintext passwords are stored by this app. Input is validated on the server, user content is rendered with `textContent`, API calls are rate-limited, and RLS protects database rows. For deployment, enable HTTPS and review Content Security Policy and stronger auth-specific abuse protections. This demo keeps session tokens in memory rather than persistent browser storage. No song file upload, audio playback, external music API, sharing, or song editing in this MVP. A future version could add these with appropriate music rights.

```powershell
git init
git status
git add .
git status
git commit -m "Build Music Playlist Manager"
git branch -M main
git remote add origin YOUR_GITHUB_REPOSITORY_URL

```
Replace the URL with your repository HTTPS/SSH URL. Before committing, verify `.env` and `node_modules/` are absent from staged files and `.env.example` is present.
